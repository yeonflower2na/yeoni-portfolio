## 에이전트 이름

pd-reference-blueprint

## 역할 (Role)

프로젝트 설명을 주면, 참고할 만한 레퍼런스 사이트를 모아서 실제로 하나씩 접속해 확인하고,
각 사이트에서 "무엇을 가져오고 / 무엇은 가져오지 말고 / 우리 화면 어디에 적용할지"를 정리한 뒤,
화면 구성 초안까지 하나의 문서(.md)로 만들어주는 에이전트입니다.

## 제작 배경

레퍼런스 사이트를 하나씩 찾아보는 것, 그걸 바탕으로 기획 방향을 잡는 것도 매번 시간이 오래 걸려 자동화하고 싶었습니다.
원래는 사이트를 하나하나 열어보며 직접 확인해야 하는 작업인데,
이 과정을 에이전트에게 대신 맡기고 정리된 결과만 받도록 만들었습니다.

## 에이전트 Workflow

1. 프로젝트 확인 (어떤 서비스인지, 목표가 뭔지 묻기)
2. 참고 사이트 후보 15~20개 모으기
3. 실제 접속해서 확인
4. 사이트마다 가져올 것 / 버릴 것 / 적용할 위치 정리
5. 정리한 근거를 조합해 방향 잡기 ("A의 구조 + B의 색감 + C의 버튼" 식으로)
6. 화면 구성 초안 작성
7. 문서(.md)로 저장
8. 메인 대화창에는 3줄 요약만 남기기

## 실험해본 것

**제작 과정**

- 레퍼런스를 그냥 모으지 않고, 사이트마다 가져올 것 / 가져오지 말 것 / 적용할 위치 / 주의할 점으로 나눠 정리하도록 규칙을 정함
- 지어내기 방지 규칙 추가 — 실제 접속해 확인되지 않은 사이트는 결과에 넣지 않고, 왜 뺐는지 이유와 함께 기록
- 특정 사이트에만 의존하지 않고 여러 디자인 갤러리와 실제 서비스를 함께 찾아보도록 구성
- 결과물을 디자인 그림이 아니라, 섹션·배치·근거·예시 문구를 글로 정리한 초안으로 정의
- 특정 문구('레퍼런스 찾아줘' 등)를 말하면 따로 부르지 않아도 이 에이전트가 자동으로 나서도록 설정
- 실제로 써보며 겪은 문제를 반영해, 잘 안 막히는 사이트를 먼저 찾는 규칙과 스스로 결과를 점검하는 단계를 추가

**실행**

- 에이전트를 설치한 뒤, "여행 예약 앱 랜딩페이지 레퍼런스 찾아줘"라고 입력
- 에이전트가 알아서 "일반 여행 소비자용"이라는 전제를 정하고, 사이트 모으기 → 확인 → 정리 → 화면 초안까지 스스로 진행

## 결과

- Airbnb·Skyscanner 등 대형 여행 사이트는 접속이 막히거나 빈 화면으로 떠서, 왜 뺐는지 이유와 함께 기록
- 근거 정리: 사이트마다 "가져오지 말 것"까지 채워짐
- 스스로 점검: 결과를 다 만든 뒤 스스로 약점을 찾아냄 — "통과한 15개 중 4개가 그룹 투어 쪽에 쏠려 있고, 정작 핵심인 항공/호텔 검색 사이트는 3개뿐"이라며 사람이 더 확인할 부분을 짚어줌
- 지어내지 않음: 링크를 지어내지 않고 가짜 링크를 만들지 않으려고 제외
- 화면 구성 초안 9단계: 섹션마다 배치·참고 사이트·예시 문구를 글로 정리

> (++ 시각적으로도 보고 싶어서 개인적으로 웹 버전도 만들어봤는데,
> 웹 버전은 Playwright으로 화면을 직접 열어 확인하다 보니 대형 사이트가 에이전트 버전보다 덜 막혔습니다.
> 같은 방식이라도 붙이는 도구에 따라 결과가 달라지는걸 확인)

## 느낀점

서브 에이전트를 써보니, 사이트 수십 개를 확인하는 어수선한 과정을 에이전트가 맡아주고
정리된 결과만 받아 곧바로 기획에 집중할 수 있어 좋았습니다.
어떤 일을 맡길지 방향만 잘 잡으면, 제 업무에도 더 효율적으로 활용할 수 있겠다는 생각이 들었습니다.
